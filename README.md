║   ✦  Bugs are symptoms — find the root cause, not the fix     ║
║   ✦  Prevention is always more valuable than detection        ║
║   ✦  Collaboration with devs is the real quality gate         ║
║   ✦  A good bug report saves more time than it takes to write ║

╚═══════════════════════════════════════════════════════════════╝

**How I approach a new feature to test:**

1. Read the requirement / ticket twice — once for what it says, once for what it implies
2. Map happy path → edge cases → negative cases → security-adjacent cases
3. Write test cases before execution, not during
4. Execute, log defects with clear repro steps + evidence
5. Retest fixes, run a focused regression pass around the change
6. Close the loop with the dev + product owner

I work at the intersection of **manual testing rigor** and **engineering curiosity** —
digging into requirements before a single test case is written, tracing bugs back to
their root cause instead of just their symptom, and treating the dev team as a partner
in quality rather than a wall to throw bug reports over.

Outside of day-to-day QA work, I spend time writing small Python tools to speed up
repetitive testing tasks, and poking at security-adjacent topics (like WPS/Wi-Fi
research) to keep a tester's eye sharp for how things actually break.
